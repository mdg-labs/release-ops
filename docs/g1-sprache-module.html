Variablen, Typen, Funktionen, Module & Imports

Das Fundament, auf das jede spätere Projekt-Phase zurückgreift — anhand von Beispielen, die mit release-monitor nichts zu tun haben, damit du das Muster wirklich verstehst statt es nur abzutippen.

Lernziel

Variablen deklarieren und typisieren. Funktionen in zwei Schreibweisen schreiben und lesen. Verstehen, was export/import tatsächlich tun — und drei verschiedene "Woher kommt das?"-Fälle unterscheiden. Schleifen, insbesondere for...of.

Variablen

let und const ersetzen das alte var vollständig — nutze const als Standard, let nur wenn sich der Wert wirklich später ändert:

const greeting = "hello";   // darf nie neu zugewiesen werden
let counter = 0;             // darf sich ändern
counter = counter + 1;       // ok
greeting = "hi";              // Fehler: Assignment to constant variable

const heißt "diese Variable zeigt immer auf denselben Wert" — bei Objekten/Arrays (siehe G2) heißt das nicht, dass der Inhalt unveränderlich ist, nur die Variable selbst.

Typen

TypeScript kennt die JavaScript-Basistypen plus eigene Konstrukte obendrauf. Die wichtigsten Basistypen:

TypBeispielwert
string"hello"
number42, 3.14 — es gibt keinen getrennten Integer-Typ
booleantrue, false
null / undefined"bewusst leer" vs. "noch nie gesetzt" — die Unterscheidung ist in der Praxis oft egal, aber APIs geben meist gezielt null zurück, wenn "kein Wert" ein gültiges Ergebnis ist

TypeScript kann Typen meist selbst erschließen (Type Inference) — du musst nicht überall explizit annotieren:

const age = 34;              // TypeScript weiß: number, ohne dass du es hinschreibst
const age2: number = 34;     // dasselbe, nur explizit

Explizit wird's wichtig bei Funktionsparametern — die kann TypeScript nicht erraten:

Funktionen

Zwei gleichwertige Schreibweisen, die dir überall begegnen werden:

// Function Declaration
function double(n: number): number {
  return n * 2;
}

// Arrow Function, einer Konstante zugewiesen
const double2 = (n: number): number => {
  return n * 2;
};

// Arrow Function, Kurzform ohne geschweifte Klammern (bei genau einem return-Ausdruck)
const double3 = (n: number): number => n * 2;

Alle drei sind funktional identisch. In diesem Projekt siehst du überwiegend Arrow Functions, weil sie sich gut in Objekte einbetten lassen (relevant in G2 bei Interfaces). Die Signatur (n: number): number heißt: "nimmt einen Parameter n vom Typ number, gibt einen Wert vom Typ number zurück." Fehlt der Rückgabewert (z.B. bei console.log-Aufrufen), ist der Typ void — das musst du aber fast nie selbst hinschreiben, TypeScript erschließt es.

Optionale Parameter

Ein ? nach dem Parameternamen macht ihn optional — der Typ wird automatisch um undefined erweitert:

function greet(name: string, title?: string): string {
  if (title) {
    return `${title} ${name}`;
  }
  return name;
}

greet("Ada");              // "Ada"
greet("Ada", "Dr.");        // "Dr. Ada"

Schleifen

Für "geh jedes Element eines Arrays durch" ist for...of die gängigste Wahl — lesbarer als die klassische for-Schleife mit Zähler, und anders als .forEach() funktioniert es korrekt mit await im Rumpf (dazu mehr in G2):

const fruits = ["apple", "banana", "cherry"];

for (const fruit of fruits) {
  console.log(fruit);
}
// apple
// banana
// cherry

Die klassische for-Schleife (for (let i = 0; i < fruits.length; i++)) funktioniert weiterhin, wird aber nur noch gebraucht, wenn du den Index selbst brauchst.

Module: export & import

Jede .ts-Datei ist ein eigenes Modul. Was du nicht explizit mit export markierst, ist von außen unsichtbar:

// math.ts
export function double(n: number): number {
  return n * 2;
}

export const PI = 3.14159;

function helper() { /* ... */ }  // NICHT exportiert — nur innerhalb von math.ts nutzbar

In einer anderen Datei importierst du gezielt, was du brauchst — das nennt man einen Named Import, weil der Name exakt passen muss:

// main.ts
import { double, PI } from "./math.js";

console.log(double(21)); // 42

Die drei "Woher kommt das?"-Fälle

Import-PfadBedeutung
import { z } from "zod"Ein npm-Paket — installiert via npm install, liegt in node_modules.
import { readFileSync } from "node:fs"Ein in Node.js eingebautes Modul. Das node:-Präfix macht explizit, dass es sich nicht um ein npm-Paket handelt (früher schrieb man nur "fs" — beides funktioniert, node: ist heute best practice).
import { double } from "./math.js"Eine eigene, relative Datei in deinem Projekt.

Der Stolperstein, der jeden TS/Node-Einsteiger einmal erwischt

Bei relativen Imports schreibst du .js — auch wenn die Datei tatsächlich math.ts heißt! Das liegt an "module": "NodeNext" aus Phase 00: Node führt am Ende immer .js-Dateien aus (TypeScript wird ja zu JS kompiliert), und die Modulauflösung erwartet deshalb schon im Quellcode die spätere .js-Endung. tsx versteht das beim Entwickeln trotzdem richtig. Lässt du die Endung ganz weg (wie du es evtl. aus älteren Tutorials kennst), meldet TypeScript mit "module": "NodeNext" einen Fehler.

Default Exports (nur zur Kenntnis, wir nutzen sie kaum)

Es gibt auch export default für "eine Hauptsache pro Datei" — der Name beim Import ist dann frei wählbar. In diesem Projekt nutzen wir durchgehend Named Exports, weil sie beim Umbenennen/Refactoring sicherer sind (dein Editor findet alle Stellen), aber du wirst export default in anderen Projekten sehen:

// config.ts
export default function loadConfig() { /* ... */ }

// main.ts — der Name ist hier frei wählbar, keine geschweiften Klammern
import loadConfig from "./config.js";

Übung (losgelöst vom Projekt — reines Sprach-Training)

Leg einen Ordner src/playground/ an (kein Teil von release-monitor, nur zum Üben):

  1. src/playground/temperature.ts: exportiere eine Funktion celsiusToFahrenheit(celsius: number): number, die nach der Formel °F = °C × 9/5 + 32 umrechnet.
  2. Dieselbe Datei: exportiere eine zweite Funktion formatFullName(first: string, last: string): string, die "Nachname, Vorname" zurückgibt.
  3. src/playground/run.ts: importiere beide Funktionen (denk an die .js-Endung!) und logge jeweils ein Testergebnis.
  4. Erweitere run.ts um ein Array mit 3 Vornamen und logge sie per for...of-Schleife durch.
  5. Führ die Datei mit npx tsx src/playground/run.ts aus.

Erfolgskriterium

Alle Log-Ausgaben erscheinen ohne Fehler. Du kannst erklären, warum import { celsiusToFahrenheit } from "./temperature.js" auf eine Datei namens temperature.ts zeigt, ohne dass das ein Widerspruch ist.
