Reference

Tech stack

One container for self-hosting: Next.js (COSS UI) and Go (auth, API, polling) in the same image. Single SQLite file app.db on volume /data.

Repository layout (target)

release-ops/
  apps/web/          # Next.js App Router, COSS — UI + Go API proxy
  cmd/server/        # Go: HTTP API + poll scheduler + auth
  internal/          # Go packages (api, poll, providers, store, crypto)
  docker/            # entrypoint.sh
  Dockerfile         # Single image: Next standalone + Go binary
  migrations/        # SQL migrations for app.db (golang-migrate)
  scripts/ci/        # create-draft-release.mjs, build-push helpers
  .github/workflows/ # pr, dev, main, release + reusable workflows
  VERSION            # Semver — release tag v{VERSION} on main bump
  docs/              # This specification
  docker-compose.yml # Single service: release-ops

Intentionally not used (MVP)

  • No multi-container deploy — no separate web + worker Compose.
  • No YAML config — everything via UI + app.db.
  • No Node worker — polling only in Go.
  • No Drizzle — Go stack uses sqlc + golang-migrate.
  • No OAuth/social login in MVP — email/password via Go session auth.
  • No Bitbucket / Azure DevOps — MVP: five source kinds; Phasical + Jira + Linear tickets.
  • No Redis/Postgres — SQLite is enough for single-instance self-host.
