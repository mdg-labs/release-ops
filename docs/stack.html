Referenz

Tech-Stack

Zwei-Prozess-Architektur: Go für Worker + API, Next.js für UI + Auth. SQLite bleibt die einzige persistente Datenbank — aufgeteilt in zwei Dateien wegen SQLite-Schreibkonflikten.

Repository-Layout (Ziel)

release-ops/
  apps/web/          # Next.js App Router, COSS, BetterAuth
  cmd/worker/        # Go: HTTP API + Poll-Scheduler (ein Binary)
  internal/          # Go packages (api, poll, providers, store, crypto)
  migrations/        # SQL-Migrations für app.db (golang-migrate)
  scripts/ci/        # create-draft-release.mjs, build-push helpers
  .github/workflows/ # pr, dev, main, release + reusable ci / prepare-release / build-and-push
  VERSION            # Semver — Release-Tag v{VERSION} auf main bump
  docs/              # Diese Spezifikation
  docker-compose.yml

Backend — Go

WerkzeugWarum
Go 1.22+Ein Binary für API + Background-Worker; gute Fit für Polling, HTTP-Clients, SQLite; kleines Container-Image.
chi oder echoLeichtgewichtiger HTTP-Router für REST-API.
modernc.org/sqlite oder github.com/mattn/go-sqlite3SQLite ohne CGO bevorzugt (modernc) für einfachere Cross-Builds; CGO-Variante wenn Performance kritisch.
sqlcTypisierte Queries aus SQL — Schema in docs/schema.sql + Migrations als Source of Truth.
golang-migrateVersionierte Migrations wie im alten Drizzle-Modell — kein push, nur up beim Start.
robfig/cronScheduler für Poll-Loop (Alternative: time.Ticker wenn Cron-Features nicht gebraucht).
github.com/golang-jwt/jwt/v5JWT-Validierung (BetterAuth JWKS) für API-Auth.
github.com/containrrr/shoutrrrNotifications an Slack, ntfy, Discord, … via URL-Schema — keine eigenen Chat-Clients.

Bewusst nicht genutzt (MVP)

  • Kein YAML-Config — alles über UI + app.db.
  • Kein Node-Worker — Polling nur in Go.
  • Kein Drizzle — Go-Stack nutzt sqlc + golang-migrate.
  • Kein Express/Fiber im Frontend — Next.js Server Routes reichen.
  • Kein OAuth/Social Login im MVP — nur Email/Password (BetterAuth).
  • Kein Bitbucket / Azure DevOps — MVP: fünf Source-Kinds; Phasical + Jira + Linear Tickets.
  • Kein Redis/Postgres — SQLite reicht für Single-Instance Self-Host.
