<p class="lede">One container for self-hosting: Next.js (COSS UI) and Go (auth, API, polling) in the same image. Single SQLite file <code>app.db</code> on volume <code>/data</code>.</p>

  <h2>Repository layout (target)</h2>
  
```
release-ops/
  apps/web/          # Next.js App Router, COSS — UI + Go API proxy
  cmd/server/        # Go: HTTP API + poll scheduler + auth
  internal/          # Go packages (api, poll, providers, store, crypto)
  docker/            # entrypoint.sh
  Dockerfile         # Single image: Next standalone + Go binary
  migrations/        # sqldiff-generated SQL only (golang-migrate applies)
  db/schema.sql      # Canonical DDL — edit then migrate-diff
  scripts/migrate-diff.mjs
  scripts/ci/        # check-migrations-sync.mjs, create-draft-release.mjs
  .github/workflows/ # pr, dev, main, release + reusable workflows
  VERSION            # Semver — release tag v&#123;VERSION&#125; on main bump
  docs/              # This specification
  docker-compose.yml # Single service: release-ops
```


  <h2>Backend — Go</h2>
  <table>
    <tr><th>Tool</th><th>Why</th></tr>
    <tr><td><code>Go 1.22+</code></td><td>API + background polling in one process; small binary in the container image.</td></tr>
    <tr><td><code>chi</code></td><td>HTTP router for the REST API (locked for MVP).</td></tr>
    <tr><td><code>modernc.org/sqlite</code></td><td>SQLite driver without CGO — easier cross-builds in Docker (locked for MVP).</td></tr>
    <tr><td><code>sqlc</code></td><td>Typed queries from SQL — schema path <code>migrations/</code> (generated from <code>db/schema.sql</code>).</td></tr>
    <tr><td><code>sqldiff</code></td><td><code>scripts/migrate-diff.mjs</code> — generates <code>migrations/*.sql</code> from <code>db/schema.sql</code> (SQLite, free).</td></tr>
    <tr><td><code>golang-migrate</code></td><td>Applies versioned migrations — <code>up</code> in container entrypoint.</td></tr>
    <tr><td><code>robfig/cron</code></td><td>Poll scheduler — interval from <code>poll_interval_minutes</code> (locked for MVP).</td></tr>
    <tr><td><code>golang.org/x/crypto/bcrypt</code></td><td>Password hashing for admin login.</td></tr>
    <tr><td><code>github.com/alexedwards/scs/v2</code></td><td>Session cookies + SQLite session store.</td></tr>
    <tr><td><code>github.com/containrrr/shoutrrr</code></td><td>Notifications to Slack, ntfy, Discord, … via URL schemes.</td></tr>
  </table>

  <h2>Intentionally not used (MVP)</h2>
  <ul>
    <li><strong>No multi-container deploy</strong> — no separate <code>web</code> + <code>worker</code> Compose.</li>
    <li><strong>No YAML config</strong> — everything via UI + <code>app.db</code>.</li>
    <li><strong>No Node worker</strong> — polling only in Go.</li>
    <li><strong>No Drizzle</strong> — Go stack uses sqlc + sqldiff-generated migrations (<code>scripts/migrate-diff.mjs</code>).</li>
    <li><strong>No OAuth/social login</strong> in MVP — email/password via Go session auth.</li>
    <li><strong>No Bitbucket / Azure DevOps</strong> — MVP: five source kinds; Phasical + Jira + Linear tickets.</li>
    <li><strong>No Redis/Postgres</strong> — SQLite is enough for single-instance self-host.</li>
  </ul>
