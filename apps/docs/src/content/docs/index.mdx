## What Release Ops is

Release Ops is a self-hosted dependency-update bot. One GitHub App runs the unmodified, open-source Renovate engine for every repository it is installed on, and opens the update pull requests as its own bot user. Release Ops creates a ticket in Kaneo, Jira or Linear for each update PR and keeps the ticket in step with the PR.

- **Updates:** Renovate opens and updates the PRs. Ticking a checkbox in a PR or in the Dependency Dashboard starts a run for that repository straight away when GitHub can reach your webhook.
- **Tickets:** One ticket per update PR, in the Kaneo, Jira or Linear project you choose. Each project has its own status mapping.
- **Sign-in:** People sign in with GitHub through the same App and get an admin or viewer role from their GitHub organization and team membership.

You run it yourself with Docker Compose: one service for the app and one for the worker that runs Renovate.

## How it works

```text
GitHub                    Release Ops                  Your ticket system
Repositories with   →     Worker runs Renovate    →    One ticket per
a Renovate config         and opens update PRs         update PR, kept in
                          App tracks each PR           step with the PR
```

1. **Install:** You create the GitHub App from Release Ops' setup page and install it on your repositories.
2. **Run:** A webhook, a Renovate checkbox, a push or an hourly run starts a job. The worker runs Renovate for that repository, and Renovate opens or updates the update PRs.
3. **Track:** Release Ops creates a ticket for each update PR and moves it as the PR is merged or closed.

## Who it is for

Release Ops is for small self-hosting dev and ops teams, and for individuals, who already use or want Renovate and want its update PRs to show up as work in their ticket system. It removes the manual step of turning each update into a ticket.

## What it is not

Release Ops keeps a deliberately small scope:

- **GitHub only.** The platform is github.com. Renovate still reads releases, tags and packages of other hosts as sources of updates.
- **No release monitoring.** It does not watch upstream projects for new releases. Tickets follow update PRs.
- **No notification channels.** Your ticket system and GitHub already notify you.
- **No local accounts.** There are no passwords, no mail and no invitations. GitHub is the only sign-in.
- **One installation per instance.** An instance has one GitHub App with one installation.
